# 业务模型与边界

数据集字段版本、授权事件、处理目的树和字段谱系共同决定请求是否可交付；撤回事件在请求时刻之前生效。

## 实体关系

历史数据集版本如发生字段重命名，配置中的 `version_mappings` 必须逐字段声明旧名到当前名的映射；没有映射的版本或字段进入无法判定，不能默许同名兼容。

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 首版以外的自然扩展

跨组织委托链、目的兼容仲裁、二次转售限制、隐私预算绑定、授权签名、访问日志后核、主体更正传播、多方许可交集。以上均未实现。

## 主体现委托链（已实现）

委托链以事件为边、主体与受托方为节点。`delegate_source` 是链根，冻结撤回合同与是否允许转委托；后续 `delegate` 只能在不扩大字段、目的和期间的条件下转授。求值时只使用请求时刻可见的事件，按 UTC 时刻与事件键稳定排序，同一时刻撤回优先。

两条独立的合法性：单级合法性（签发者、来源、交集、目的祖先、半开期间）与链级合法性（每级都不放大、不得在父撤回后新签、不得使用分叉链拼接字段）。前者产生拒绝，后者中的结构性缺陷（缺来源、异文、环、父授权缺失、链冲突）产生无法判定。委托结构无法证明不存在其他可达链时，不因“图可达”放行。

撤回效力只由链根的 `revocation_effect` 决定。`immediate` 合同下任一级撤回使整链失效；`fixed_term` 下，撤回前已签、且 `irrevocable_until` 覆盖请求时刻的末级子委托继续有效直至该期限，但其上层已撤回，之后不得再签发新的下级。子事件自行声明的合同或期限只能收窄，不能把源合同改成另一种。

证据表 `delegation_chain`/`delegation_link` 与 run 绑定：每级保存事件键、RawEvent 与 SourceFile 引用、来源 SHA、字段交集、期间、合同效力与结论。报告和 `delegation-report` CLI 读取这些冻结行，重新导出历史 run 不改变过去结论；`verify` 额外核对每级事件的摘要与来源一致性。
