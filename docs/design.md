# 业务模型与边界

数据集字段版本、授权事件、处理目的树和字段谱系共同决定请求是否可交付；撤回事件在请求时刻之前生效。

## 实体关系

历史数据集版本如发生字段重命名，配置中的 `version_mappings` 必须逐字段声明旧名到当前名的映射；没有映射的版本或字段进入无法判定，不能默许同名兼容。

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 主体更正传播

更正不直接改写原值：`correction_plan` 冻结快照原文、成员、指标合同、更正原文与授权 run；校验失败（旧值不匹配、同键异文、同时刻互斥更正、缺成员、缺指标定义、摘要损坏）只留 `plan_issue` 并阻断该 cohort 的新版本。通过校验后 `cohort_version` 按固定精度（算术均值两位小数、降序密集并列名次）重算全体成员，版本绑定真实贡献者集合而非字段名，并记录逐贡献者授权证据摘要。

历史效力由计划时冻结的合同决定：`retroactive_restate` 重述原生效日权威结果并把旧版本标 `superseded`（原文保留）；`prospective_version` 保留旧版本在更正登记时点前的权威性（`archived`），新版本自登记时点起生效。合同不能按查询切换，被取代的旧版本不能冒充当前值。派生字段（`cohort_rank`、`mean`）的授权门要求版本内每个贡献者在请求目的、源 `score` 谱系与时点上各自获许可；证据不足或更正冲突时派生值无法判定。

## 首版以外的自然扩展

跨组织委托链、目的兼容仲裁、二次转售限制、隐私预算绑定、授权签名、访问日志后核、多方许可交集。以上均未实现。
