# 业务模型与边界

数据集字段版本、授权事件、处理目的树和字段谱系共同决定请求是否可交付；撤回事件在请求时刻之前生效。

## 实体关系

历史数据集版本如发生字段重命名，配置中的 `version_mappings` 必须逐字段声明旧名到当前名的映射；没有映射的版本或字段进入无法判定，不能默许同名兼容。

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 交付释放协议

`delivery_package.state` 描述业务意图，不描述文件是否真的落盘。一次释放由 `delivery_release` 的冻结意图驱动：包身份（request/run/manifest/values 摘要）、绝对目标路径、待发布文件路径与预期载荷 SHA-256 在写入任何字节前提交。之后是四个可独立崩溃的窗口：写临时文件（fsync）、提交台账、原子更名（link/replace 不覆盖既有目标）、最终确认。

恢复 (`recover`) 只依据重算结果分类：

| 观察 | promote_verified | require_reapproval |
| --- | --- | --- |
| 目标已有逐字节一致的载荷 | 已交付（确认） | 已交付（确认，不回滚） |
| 目标已有异文 | 内容冲突，不覆盖 | 内容冲突，不覆盖 |
| 待发布文件完整且授权有效 | 原子晋升并确认 | 隔离，待重新授权 |
| 待发布文件完整但授权已变 | 拒升，证据不完整 | 隔离，待重新授权 |
| 待发布文件缺失/损坏 | 证据不完整 | 证据不完整；隔离损件并置为待重新授权 |
| 无释放意图但台账声称 released | 证据不完整 | 证据不完整 |

恢复记录 (`delivery_recovery`) 只追加，保存依据的台账、文件摘要、授权状态与结果。旧版本台账在首次触达时迁移：只有当已释放文件仍存在且可重算一致才补写交付证明，否则保持无证明，后续使用审计为不确定。

用后审计不读取 `state` 字符串作为交付证明，而是要求 `delivery_release.status='delivered'`、目标字节摘要与冻结载荷一致、内容可重算出包摘要，全部成立才进入授权时点核查。

## 首版以外的自然扩展

跨组织委托链、目的兼容仲裁、二次转售限制、隐私预算绑定、授权签名、访问日志后核、主体更正传播、多方许可交集。以上均未实现。
