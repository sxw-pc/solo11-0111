# 业务模型与边界

数据集字段版本、授权事件、处理目的树和字段谱系共同决定请求是否可交付；撤回事件在请求时刻之前生效。

## 实体关系

历史数据集版本如发生字段重命名，配置中的 `version_mappings` 必须逐字段声明旧名到当前名的映射；没有映射的版本或字段进入无法判定，不能默许同名兼容。

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 首版以外的自然扩展

跨组织委托链、目的兼容仲裁、二次转售限制、隐私预算绑定、授权签名、访问日志后核、主体更正传播、多方许可交集。以上均未实现。

## 离线授权来源轮询优化

`polling.py` 在不访问网络的前提下，对合成来源的采集动作做有限时域精确优化。预测原文（来源、逐槽有理更新概率、权重、总轮询预算、每槽容量、目标合同）与其 SHA-256 一并冻结到 `poll_forecast`；人工计划保留在 `poll_manual_plan`，最优计划写入 `poll_opt_plan`，相同 ID 的异文一律冲突拒绝，相同请求幂等返回冻结结果。

每槽陈旧概率按 `q_t = 1 − (1 − q_{t−1})(1 − p_t)` 演化，槽末轮询该源则 `q_t = 0`；期望陈旧暴露为各源权重乘逐槽 `q` 之和，最长未轮询间隔从时域起点 0 计到各次实际轮询，所有源必须在最后槽完成封账轮询。求解用保留“各源上次轮询槽、已用预算、前驱指针”的有限时域 DP，同一状态仅保留帕累托最优的（暴露、最大间隔）标签，并按槽序、源 ID 序稳定破同分。两份固定合同 `min_expected_stale`（先暴露后间隔）与 `min_max_gap`（先间隔后暴露）从同一次求解取各自胜者；全部暴露在公共整数单位内运算，输出再还原为精确分数。预算耗尽时给 `indeterminate` 与已证上下界，绝不把可行在选计划冒称最优。

`poll-verify` 只信冻结的预测原文与计划字节，独立重算逐槽 `q`、预算与容量约束，并用同一精确 DP 重新推导全局最优，可识别漏轮询、乘积错算、概率篡改与次优替换；发现的问题以 `poll_verify:*` 码返回。
